## 维护规则

- **同一改动里更新。** 改动影响到页面上写的职责、接口、状态变化、运行路径、约束或失败行为时，在同一次改动里更新对应页面。
  不改变这些内容的内部重构，不需要改文档。
- **按文档职责维护事实。** `README.md` 面向使用者写功能概览与构建方式；`AGENTS.md` 写工作入口、目录职责和命令；`requirements.md` 写目标、验收标准和验证状态；`code-standards.md` 写通用规则；子系统页面写当前运行方式、约束和实测依据；`LESSONS.md` 留规则背后的错误证据。概览可概括功能，具体实现、阈值与测量结论只在所属页面维护，其他文档链接过来。
- **链接源码，少抄实现。** 链接源码文件和具体符号名，不要照抄容易变动的实现细节。
  写清楚签名本身表达不了的含义和约束，以及数据背后的实测依据。
- **只写现在。** 设想中的改动写在提交说明或任务里；被放弃的方案只在「约束」里留一句为什么不用；过时的内容直接删掉，历史查 git。
