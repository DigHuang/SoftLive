# 需求

SoftLive 现在要做到什么、做到什么程度算完成。直接在原文上更新：需求变了就改，不再需要的就删掉。
实现方式见 [子系统参考](subsystems/README.md)。

## 目标

在 macOS 上，把 **网易云音乐** 和 **Apple Music** 正在播放的歌词，同步显示在 **状态栏**、**桌面悬浮窗** 和 **桌面组件** 里。
自己实现，可以参考开源方案里有价值的做法，但不直接使用它们。

## 功能

| 需求 | 验收标准 | 状态 |
| --- | --- | --- |
| 跟随 Apple Music | 识别当前歌曲；播放、暂停、切歌、拖动进度后，歌词在 2 秒内跟上 | ✅ 完整播放流程未端到端测试（资料库为空） |
| 跟随网易云音乐 | 识别当前歌曲；播放、暂停、切歌后歌词跟上，网易云窗口在后台时同样有效 | ✅ 实测换歌识别延迟 0.1–0.3 秒 |
| 网易云拖动进度后同步 | 拖动后约 2 秒内跟上，误差 ≤ 1 秒，之后继续收敛 | ✅ 实测：记录到达后 2 ms 完成修正 |
| 状态栏歌词 | 显示当前行；有宽度上限，长句截断 | ✅ |
| 桌面悬浮歌词 | 置顶，所有桌面空间可见，全屏 App 上也可见，不抢焦点；可拖动；可锁定为鼠标穿透；第二行显示翻译或下一句 | ✅ |
| 桌面组件 | 位于所有窗口之下、桌面图标之上；显示封面、曲目、逐字当前句、翻译、下一句和进度；可拖动、记住位置 | ✅ 默认关闭，在菜单里打开 |
| 逐字歌词 | 有逐字数据（网易云 YRC）时逐字填色，没有时逐行显示 | ✅ |
| 翻译 | 有翻译时显示在对应行 | ✅ |
| 手动校正 | 菜单里可让歌词提前或延后 0.5 秒，换歌后重置 | ✅ |
| 菜单入口 | 状态栏被刘海挤掉时，右键桌面歌词或桌面组件、或再次打开 App，都能弹出菜单 | ✅ |

## 质量

| 需求 | 验收标准 | 状态 |
| --- | --- | --- |
| 原生实现 | Swift + AppKit + SwiftUI，零第三方依赖 | ✅ |
| 代码结构 | 文件结构合理，按模块分目录，不写冗余逻辑 | ✅ |
| 系统版本 | 可以不兼容旧系统，换取更优雅的实现 | ✅ 最低 macOS 26 |
| 资源占用 | 同时开启桌面歌词和桌面组件、播放逐字歌词时 CPU ≤ 1%，空闲时约 0% | ✅ 实测 0–0.8%，每秒唤醒 4–5 次 |
| 权限最少 | 网易云不需要任何系统权限；Apple Music 只需要「自动化 → Music」 | ✅ |
| 文档 | 参考 magpie 的方式维护：AGENTS.md、子系统参考、代码规范、LESSONS.md，都只写现在、持续更新 | ✅ |

## 明确不做

| 事项 | 原因 |
| --- | --- |
| WidgetKit 小组件 | 刷新频率由系统控制，做不了实时歌词 |
| 借系统二进制的授权读 MediaRemote | 属于绕过系统权限，见 [代码规范](code-standards.md) |
| 为没有逐字数据的歌估算逐字填色 | 提出过，用户没有采纳 |
| 拖动后用滚轮手动对齐 | 已经能自动同步，不需要 |
